# Issue workflow support

The prompt templates in `.pi/prompts/` use these scripts for GitHub-board actions, branch creation, and tmux-backed context/review sessions.

- `query_ready.sh`, `move_status.sh`, `add_label.sh`, `remove_label.sh`: GitHub Project and issue-label operations.
- `capture_issue.sh`: immutable issue snapshot at `docs/issue-workflows/<issue>/issue.md`.
- `create_branch.sh`: creates `feat/<issue>-<slug>` from `origin/main`; it refuses a dirty checkout.
- `open_pr.sh`: requires a clean, committed feature branch; it pushes and creates a pull request.
- `context/`: session creation, worker dispatch, and status display for context gathering.
- `../knowledge-base/source_inventory.py`: builds a deterministic, committed-source inventory for `/sync-project-wiki` and future read-only drift checks.
- `final-review/`: session creation and reviewer dispatch for final review.

## Closed issue archival

Active workflow records under `docs/issue-workflows/<issue>/` remain repository-local while an issue is being planned, implemented, reviewed, or awaiting merge. After GitHub confirms the issue is `CLOSED`, use `/archive-closed-issue <issue-number>` before discarding the branch or worktree. The prompt copies and verifies all substantive artifacts into a vault branch, opens a vault archive PR, and waits for that PR to merge and be verified on vault `main`. Only then may a separate backend cleanup PR remove exactly that repository workflow directory. Archived context is retrieved through the vault's Maps, search, properties, and backlinks; it is not generated by the issue scripts.

## tmux

The workflow creates detached tmux sessions. Attach with the command printed by the launcher, then switch directly to a worker window to inspect or steer it.

For source synchronization, use `/sync-project-wiki --mode check|plan|apply|verify`. The vault repository is separate from this backend repository; never stage vault content in a backend PR and never let CI write directly to the vault.

For reliable modified Enter keys in Pi, use the recommended tmux configuration from Pi's `docs/tmux.md`:

```tmux
set -g extended-keys on
set -g extended-keys-format csi-u
```
